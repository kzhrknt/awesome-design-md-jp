## 3. Typography Rules

### 3.1 和文フォント

- **ゴシック体**: **Noto Sans JP**。自社ドメインの **Cloudflare Fonts**（`https://www.mhi.com/cf-fonts/v/noto-sans-jp/5.2.9/<subset>/wght/normal.woff2`）から配信。フォント要求はトップで **43 件**（unicode-range 分割）
- **明朝体**: 使っていない（セリフ系の和文は 2 ページとも可視 0 要素）

**実在するウェイトは 100 / 300 / 400 / 500 / 700 の 5 本。** 同一ページ・実スタックで幅を実測すると:

| 指定 | 100 | 200 | 300 | 400 | 500 | 600 | 700 | 800 | 900 |
|---|---|---|---|---|---|---|---|---|---|
| 実測幅 | 946.20 | **946.20** | 968.45 | 1000.45 | 1024.11 | **1054.70** | 1054.70 | **1054.70** | **1054.70** |

- **200 は 100 に、600 / 800 / 900 は 700 に丸められる。** 段数は 5 段で、**合成太字は起きない**
- 実際に使われているのは **300 / 400 / 500 / 700 の 4 段**（100 は宣言のみで可視 0 要素）

> **CDP の `CSS.getPlatformFontsForNode` はこのサイトで `Noto Sans JP Thin` を返すが、Thin で描画されているわけではない。** サブセット分割された woff2 の内部名がそう返るだけで、**weight 500 の要素も weight 700 の要素も同じ名前が出る**。太さの判定は上の幅実測で行うこと。

### 3.2 欧文フォント

- **サンセリフ**: **DIN Next LT W04 mid**（自社ホストの `/themes/custom/mhi/src/mhi/fonts/*.woff2`）。カード見出しに使う（可視 9 要素）
- `DIN Next LT W04`（regular）と `DIN Next LT W04 Bold` も `@font-face` で宣言されているが、**2 ページとも `unloaded`**。幅実測でも Arial と完全一致（989.45px）で、**当たっていない**
- **ウェイトはファミリー名で切り替える設計**（`font-weight` では切り替わらない）。ただし実際に読み込まれているのは **mid の 1 本だけ**
- 数字・連番は **Arial**（可視 5 要素）

### 3.3 font-family 指定

```css
/* ① グローバルナビ・ニュース（最も多い。トップ 62 要素 / 下層 48 要素） */
font-family: "Noto Sans JP", Arial, Helvetica, sans-serif;

/* ② 本文・タグ（トップ 82 要素）— 綴りが 2 箇所壊れている */
font-family: "Noto Sans JP", "MS Pゴシッ̊", "MS PGothic",
             "ヒラギノ角ゴPro W3", "Hiragino Kaku Gothic Pro", sans-serif;

/* ③ 同じ役割の正しい綴り（.cBold など。下層 3 要素） */
font-family: "Noto Sans JP", "MS Pゴシック", "MS PGothic",
             "ヒラギノ角ゴ Pro W3", "Hiragino Kaku Gothic Pro", sans-serif;

/* ④ カード見出し（欧文書体を和文に当てている） */
font-family: "DIN Next LT W04 mid", Arial, Helvetica, sans-serif;
```

**フォールバックの考え方 — ② と ④ に事故がある。両方書く。**

- **② の `"MS Pゴシッ̊"` は実在しない名前。** `ク`（U+30AF）が **`ッ`（U+30C3）＋ U+0343（COMBINING GREEK KORONIS）**に化けている。見た目はほとんど区別できない
- **② の `"ヒラギノ角ゴPro W3"` は `角ゴ` と `Pro` の間の空白が落ちている。** CSS のフォント名照合は大文字小文字を無視するが**空白は無視しない**ので、この名前も必ず外れる
- **どちらも ASCII 名の保険（`"MS PGothic"` / `"Hiragino Kaku Gothic Pro"`）が後ろにあるので、いまは実害が出ていない。** 実害が出るのは**Noto Sans JP が届かず、かつ Windows でメイリオ以前の環境**という狭い条件
- **④ の `"DIN Next LT W04 mid"` は CJK グリフを持たない欧文ディスプレイ体。** 和文は `Arial` → `Helvetica` も外れて **末尾の `sans-serif`**（macOS ならヒラギノ角ゴ ProN）で描画される。**OS ごとに和文の字面が変わる**

**正しくはこう書く**:

```css
/* ② の修正版 */
font-family: "Noto Sans JP", "MS PGothic", "Hiragino Kaku Gothic Pro", sans-serif;

/* ④ の修正版 — 欧文と和文を分ける */
font-family: "DIN Next LT W04 mid", "Noto Sans JP", sans-serif;
```

## 7. Do's and Don'ts

### Do（推奨）

- **白地・黒文字（`#000000`）・罫線だけで組む。** 面を塗らない
- **本文は `line-height: 1.80` / weight 300**。和文を Light で広く組むのがこのサイトの声
- **`letter-spacing: normal` を貫く**（2 ページとも 100%）
- **ブランド赤 `#e31f26` は「いま見ているところ」にだけ使う**（パンくずの現在地、選択中のタブ）。CTA や帯に使わない
- **角丸はピル（`900px`）だけ。** カード・ボタンは `border-radius: 0`
- **タグは面を塗らず、`1px solid #757575` と同色の文字で作る**
- コンテナは **1296px**
- サイズは `body` に対する `%` で書く（`225%` `187%` `68%`）
- `font-weight` は **300 / 400 / 500 / 700 の 4 段**で組む

### Don't（禁止）

- **`"MS Pゴシッ̊"` を書かない。** `ク` が `ッ` + U+0343 に化けた実在しない名前で、必ず外れる（**この DESIGN.md から値をコピーするときに最も混入しやすい箇所**）
- **`"ヒラギノ角ゴPro W3"` と空白を詰めて書かない。** フォント名の空白は無視されないので外れる。正しくは `"ヒラギノ角ゴ Pro W3"`、より確実には ASCII の `"Hiragino Kaku Gothic Pro"`
- **`"DIN Next LT W04 mid"` を和文に当てない。** CJK グリフが無いので `sans-serif` に落ち、OS ごとに字面が変わる。欧文と和文は別に指定する
- **`DIN Next LT W04`（regular）と `DIN Next LT W04 Bold` を前提に組まない。** 宣言はあるが 2 ページとも `unloaded`、幅実測でも Arial と完全一致で当たっていない
- **`font-weight: 200 / 600 / 800 / 900` を使わない。** 実在するのは 100 / 300 / 400 / 500 / 700 の 5 本で、200 は 100 に、600 以上は 700 に丸められる
- **康熙部首（`⽇` U+2F47 / `⽀` U+2F40 など）を本文に混ぜない。** 通常の漢字（`日` U+65E5 / `支` U+652F）で書く
- **`linear-gradient` の停止位置を逆順（`20%` → `10%`）に書かない。** 実サイトはこうなっているが、正しくは同じ値を 2 度書いてハードストップにする
- **`font-feature-settings: "palt"` を足さない**（2 ページとも 0 要素）
- **`letter-spacing` を足さない**
- **影を足さない**（サイト本体は 0 種）
- **ヒーローの大見出しを画像で作らない。** 実サイトは 1440×540 の `<picture>` に和文コピーを焼き込み、`alt` には `Key Solutions` としか入れていない。**テキストで組むか、少なくとも `alt` に全文を入れる**
- **`rem` を使わない。** ルートが 4 段で崖が 3 箇所あるため（8.）、`rem` で書いた値は幅によって 1.7 倍以上動く

| 992 → 991px | 6.944px → **11.6938px** | **1.68 倍（跳ねる）** |

> **最小は 481px の 5.6758px。** 規定の 4 幅（1440 / 1200 / 834 / 375px）でも 6 幅でも、**3 つの崖のどれも踏まない**。
> **`rem` で書いた値は幅によって 2.8 倍の開きが出る**（16px ↔ 5.68px）。このサイトが px と `%` で書いているのはそのため。

### `body` の実測

| 幅 | `body` | 式 |
|---|---|---|
| ≥1441px | **17px** | `font-size: 17px` |
| **1440〜1367px** | **16.704px（1440px）/ 15.8572px（1367px）** | **`1.16vw`** |
| 1366〜481px | **17px** | `font-size: 17px` |
| ≤480px | **13px** | `font-size: 13px` |

> **`body` が流体になるのは 1367〜1440px の 74px 幅だけ**（`only screen and (max-width: 1366px)` が境目）。
> サイズが `body` に対する `%` で書かれているので、**この帯でだけ全体がわずかに縮む**。1440px の測定値をそのまま「このサイトのサイズ」と書くと 1366px 以下と 0.3〜2% ずれる。

### タッチターゲット

- キーワードタグは `padding: 3.5px 11.62px` ＋ 14px の文字で高さ約 32px。**44px を下回るのでモバイルでは高さを足すこと**
- グローバルナビは 17px / `line-height: 1.00` と詰まっている。**SP では別メニュー（ハンバーガー）に切り替わる**
- ニュースカテゴリの帯は `padding: 5px 40px 5px 16px` で高さ約 35px

### フォントサイズの調整

- **デスクトップとモバイルで `body` が 17 → 13px**（≤480px）。`%` で書かれたサイズはこれに追従する
- **px 直書きの箇所（ナビ 17px、メガメニュー 18px、タグ 14px）は追従しない。** モバイル用のメディアクエリで個別に上書きしている（`only screen and (max-width: 480px)` が 442 件ある理由）
