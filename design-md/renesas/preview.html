02 / Typography

和文の Web フォントを 1 本も読まない

スタックは全要素が "DM Sans", "DM Sans Fallback", Arial, sans-serif（可視 174 / 103 要素＝全部）。DM Sans も Arial も CJK を持たないので、日本語は generic の sans-serif ＝ 端末の既定和文に落ちる。

実サイトはこうだが、正しくはこう書く

CDP の CSS.getPlatformFontsForNode で実測すると、macOS では日本語が Hiragino Kaku Gothic ProN で描画される（Windows なら Yu Gothic UI、Android なら Noto Sans CJK JP）。端末ごとに字面が変わる。さらに「メモリ&ロジック」のような 1 要素の中で、和文がヒラギノ・& だけ DM Sans Medium と書体が割れる。

実サイト

推奨
…,"Noto Sans JP","ヒラギノ角ゴ ProN W3",…マイクロコントローラとマイクロプロセッサ

DM Sans Fallback は src: local("Arial") に ascent-override / descent-override / size-adjust を与えたメトリクス一致用のフォールバック（4 ウェイト分）。土台が CJK を持たない Arial なので、この工夫は和文には 1 文字も効かない。

font-weight: 500 を和文の中太のつもりで使わない。ヒラギノ角ゴ ProN は W3 / W6 の 2 本しか無いので 500 は Regular で出る。欧文（DM Sans Medium）だけが中太になり、1 行の中で太さが揃わない。

このサイトの読み方

レイアウト・色・コンポーネントは参考にしてよいが、書体の調達だけは真似しない。日本語ページなのに和文の Web フォントを 1 本も読まず、font-family の受け皿も Arial, sans-serif で終わっている。本リポジトリでは「和文タイポグラフィを設計していない例」として収録している。

ルートは html { font-size: 16px } 固定で、1920〜320px の 25 幅すべてで動かない。崖は 992/991px の 1 箇所だけで、h1 が 44 → 32px、h2 が 38 → 26px に落ちる。
