ウェイトは 400 / 500 / 700 の 3 段だけ。@font-face も 3 本しかないので、600 や 900 を当てると合成太字になる。実測で 600 が出るのは CMP（Cookie 同意）の 2 要素だけで、サイト本体には存在しない。

字間 0.04em の継承のしかたがページで正反対。トップは body に 1 行書いて 0.64px として px で降る（215 要素）ので、60px の見出しでも字間は 0.64px のまま＝実質 0.011em。ブランドページは各要素が 0.04em を持ち直すので、サイズに比例して px が変わる（33.7335px → 1.34934px、14.7584px → 0.590337px）。片方だけ見て設計を決めないこと。

07 / Layout & Responsive
LAYOUT

1320 / 1200 / 800

コンテナはトークンで持つ。--wideW: 1320px（実測 9 要素で最多）、--contentsW: 1200px、読み物は --innerW: 800px。ヘッダーの高さと赤帯の太さもトークン（PC 128px / 4px、タブレット 80px / 4px、SP 56px / 3px）。

--wideW: 1320px
--contentsW: 1200px
--innerW: 800px（読み物）
--l_2colLayout_localNav_width: 282px

ルートは 16px 固定、動くのは body だけ

html に font-size の宣言が 1 つも無いので、1920px から 360px まで UA 既定の 16px で固定。動くのは body の 2 段（16px ／ 767px 以下 15px）だけで、継承される字間も 0.64px → 0.6px に下がる。

ブランドページの vw 直書きには下限が無い

clamp(min, calc(N / var(--pcDesignWidth) * 100vw), Npx) を使う宣言群と、font-size: 1.02489vw のような素の vw 直書きが同じページに同居している。後者には下限が無く、768px で 8px を切る。

規定の 4 幅（1440 / 1200 / 834 / 375px）では崖が見えない。834px でも「ただの流体」に見えるので、max-width の値 ±1px を必ず測ること。新規実装では clamp() 側に揃え、下限を付ける。

文字サイズのトークンは PC と SP の 2 組を持つ（--fontM: 16px / --fontM_sp: 15px ほか）。メディアクエリで変数を差し替えるのではなく、_sp 付きの別トークンを参照するのがこのサイトの流儀。
