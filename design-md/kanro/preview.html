font-weight: 700 を使わないこと。Noto Sans JP は可変フォントなので、書けば本当に太く出てしまう（欧文実測で 100 → 1072.11px … 900 → 1228.20px と 9 段すべて別の幅）。

font-feature-settings: "palt" を足さないこと。実サイトは 1 件も宣言していない。ただし書体は機能を持っており、実スタック 100px で normal 2150.00px → "palt" 1799.91px（−16.28%）と効いてしまう。「できるのにやっていない」型。

トークンに名前があっても使われているとは限らない。--font-ch（Noto Sans SC）/ --font-roboto / --font-zenmaru は宣言されているが、1 要素も描画していない。判定は常に ①document.fonts ②distributions.fontFamily の可視件数 ③フォント要求の件数 の 3 点で行う。

和文スタックが "Noto Sans JP", sans-serif の 2 語しかない。ヒラギノも游ゴシックも書かれていないので、Web フォントが落ちると端末既定のサンセリフに落ちる。実サイトはこうだが、正しくは "ヒラギノ角ゴ ProN W3", "Hiragino Kaku Gothic ProN", "游ゴシック Medium", "Yu Gothic Medium", メイリオ, Meiryo を足したほうがよい（このプレビューではそうしている）。

05 / Responsive

Root Scaleルートは 4 段、崖は 768 → 767px

規定の 4 幅（1440 / 1200 / 834 / 375px）では崖が見えない。768 / 767px を測らないと「ただの流体」に見える。タブレット帯の本文が 10px 台まで縮み、モバイルのほうが大きくなる。

1.33333vw = 100vw ÷ 75 → 分母 75 × 16 = 設計幅 1200px。4.10256vw = 100vw ÷ 24.375 → 分母 24.375 × 16 = 設計幅 390px で、389px でちょうど 16px に着地するのでモバイル側の境目には段差が無い。

rem を 16px 基準で換算しないこと。サイズ・余白・角丸がすべて rem（Tailwind の --spacing: .25rem 基準）なので、幅を変えると全部が連動する。このプレビューも同じ 4 段のメディアクエリを実装しているので、ブラウザ幅を 768px と 767px で切り替えると崖が確認できる。
